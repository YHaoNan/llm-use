# Parameters

参数名|类型|必须|描述
---|---|---|---
input_path|string|是|书籍文件的路径
output_path|string|是|用于存储临时文件和总结文档输出路径，默认使用当前用户的文档目录，基于操作系统的差异，具体的情况可能不同

> 注意：在任何情况下，如果你要对书籍进行分析，你必须先将原始的二进制格式书籍的内容通过book_extract mcp工具进行提取，获得结构化的文档。

# 通用流程

1. 若temp_dir中有此前提取过的结构化文档，直接使用
2. 否则需要先对书籍内容进行提取，形成结构化文档，使用book_extract_mcp
3. 若提取失败，直接返回错误信息，不要再继续了

# 书籍结构化文档格式
```
chapter-index.json         书籍章节索引文件
images/                    书籍图片资源目录
|-- image01.png
chapters/                  书籍章节内容，平铺
|-- chapter1.md
|-- chapter1.1.md
|-- chapter1.2.md
|-- chapter2.md
|-- ...
```

# 输出文件夹结构
```
book-content  # 书籍结构化文档输出目录
summary       # 知识总结输出目录
|-- 文档1.md  # 用户指定的总结任务的文档，名称不定
|-- 文档2.md
```

关于书籍章节名称，章节之间的层级关系，都在索引文件中，章节具体的markdown文件名不确保有意义。请依赖索引文件进行工作。

# 总结书籍内容

1. 若用户未要求总结指定章节的内容，请阅读并总结全书所有章节。注意，需要读取原书内容，而不是你生成的历史总结性内容。
2. 若用户指定了要总结的章节，仅需要阅读并总结该章节的内容。注意，需要读取原书内容，而不是你生成的历史总结性内容。

产物：
文本性总结：markdown结构化文本，可以拆分成多个文本
- 概要：对整体内容有一个总结性的描述，站在较高的抽象层级，不要站在细节上
- 章节描述：对于所有章节以及子章节，摘取其主要观点以及论据，每一个观点形成一个段落。按照书内排列顺序结构化生成，如果章节内容足够复杂，请使用PlantUML生成思维导图，并通过plantuml-validator进行验证
- 总体思维导图，使用PlantUML生成思维导图，并通过plantuml-validator进行验证

输出路径：
- 概要：{output_path}/summary/${user_task_name}.md
